## Code Improvements

### 1. Wheel early-close log uses wrong sign convention (profit shown as negative when losing)
The log message says `profit=-94.8%` when the position is a loss. The formula `(sell_price - current_price) / sell_price` is correct for profit on a short option, but when current > sell, this goes negative — which is correct. However the log label "profit" is misleading when negative; it should say "P&L" to avoid confusion in review.

FILE: wheel_strategy.py
OLD:
```python
    log.info(f"EARLY CLOSE CHECK: {contract['symbol']} sell=${sell_price:.2f} now=${current_price:.2f} profit={profit_pct*100:.1f}% (target {EARLY_CLOSE_PCT*100:.0f}%)")
```
NEW:
```python
    log.info(f"EARLY CLOSE CHECK: {contract['symbol']} sell=${sell_price:.2f} now=${current_price:.2f} pnl={profit_pct*100:.1f}% (close_target=+{EARLY_CLOSE_PCT*100:.0f}%)")
```

### 2. Trailing stop never activates after a restart when price has fallen below trigger
`trailing_active` is `False` in state and `hwm=$408.42` is above the trigger (`entry_price * 1.10 = $381.21 * 1.10 = $419.33`). So the HWM check `hwm >= trigger_price` is **False** ($408.42 < $419.33), and trailing never arms — even though the position is well-established. The activation guard should also check whether the **current price** is above the trigger (not just HWM), so a position that ran up and pulled back still gets protected.

FILE: market_monitor.py
OLD:
```python
    trigger_price = entry_price * (1 + TRAIL_TRIGGER_PCT)
    if not trailing and hwm >= trigger_price:
```
NEW:
```python
    trigger_price = entry_price * (1 + TRAIL_TRIGGER_PCT)
    if not trailing and (hwm >= trigger_price or price >= trigger_price):
```

### 3. Copy trader state missing `last_politician_eval` key causes re-evaluation every run
When `last_politician_eval` is absent from state, the code sets `last_eval = today_str` and then checks `last_eval < week_ago` — which is False, so it correctly skips re-eval. But `last_politician_eval` is never written back when skipping, so the next run repeats the same logic path needlessly. The fix is to always persist the eval date when using the cached politician.

FILE: copy_trader.py
OLD:
```python
    last_eval = state.get("last_politician_eval") or today_str
    week_ago  = (datetime.now() - timedelta(days=7)).strftime("%Y-%m-%d")
    if not state.get("tracked_politician") or last_eval < week_ago:
        politician = pick_best_politician(trades)
        state["last_politician_eval"] = datetime.now().strftime("%Y-%m-%d")
    else:
        politician = state.get("tracked_politician")
```
NEW:
```python
    last_eval = state.get("last_politician_eval") or today_str
    week_ago  = (datetime.now() - timedelta(days=7)).strftime("%Y-%m-%d")
    if not state.get("tracked_politician") or last_eval < week_ago:
        politician = pick_best_politician(trades)
        state["last_politician_eval"] = today_str
    else:
        politician = state.get("tracked_politician")
        state["last_politician_eval"] = state.get("last_politician_eval") or today_str
```
